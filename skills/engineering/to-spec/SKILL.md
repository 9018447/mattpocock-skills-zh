# to-spec：用户指定 Agent，acpx 纯派发

本 Skill **不绑定任何特定 Agent**。每次执行 `to-spec`，必须先取得用户针对本次任务**明确指定的目标 Agent**，再通过 **acpx** 派发。编排者不是 spec 执行者。

## 前置条件：目标 Agent 必须由用户指定

- 目标 Agent 必须来自用户的明确指示，可以是当前请求，也可以是当前对话中明确适用于本次任务的指定。
- **没有明确指定时，先问用户要派发给哪个 Agent，然后停止；不得执行或派发。** 这只是确认派发对象，不是需求访谈。
- 不得默认使用 Kimi 或任何其他 Agent；不得根据最近一次派发、示例、模型偏好、可用性或编排者的判断推断目标。
- 使用用户指定的 Agent 标识进行 acpx 派发，不擅自改名、替换或进行兜底切换。如果目标 Agent 无法通过 acpx 使用，报告阻塞并请用户重新指定，不要改成本地执行。

## 职责边界

- **编排者**：确认用户指定的目标 Agent；检查 issue tracker 和标签配置；整理现有对话上下文；装配完整派发内容；通过 acpx 向该 Agent 派发；回传实际执行结果。
- **目标 Agent**：探索仓库及相关 ADR、使用项目领域词汇、确定测试接缝、撰写 spec、发布 issue、添加 `ready-for-agent` 标签。

编排者**不得**自行探索仓库、设计或确认测试接缝、撰写 spec、创建/编辑 issue，或在 Agent 失败后接管。不要就需求进行访谈，也不要重复询问当前对话已经明确的内容。

## 必须全文传给目标 Agent 的文件

以下两个文件是目标 Agent 的**强制执行契约**，不是供编排者概括的参考资料：

1. `references/agent-instructions.md`：完整执行步骤、决策约束、发布要求、完成标准和返回格式。
2. `templates/spec.md`：issue 正文必须严格遵循的完整 spec 模板。

**每次派发都必须先读取这两个文件，并将其全文原样嵌入给目标 Agent 的 acpx 任务消息。** 不允许只传文件路径、文件名、链接、摘要或“自行阅读”；不得省略、改写、截断、重新解释任何内容。即使目标 Agent 可以访问相同的工作目录，也必须在消息中传递全文。不能完整传递时，停止派发并说明原因。

## 派发流程

1. **确认目标 Agent**：查找用户针对本次任务的明确指定；缺失则只询问派发对象并停止，不使用默认 Agent。
2. **检查项目配置**：issue tracker 与分类标签词汇必须已提供。缺失时，告诉用户运行 `/setup-matt-pocock-skills`，停止派发；不得猜测配置。
3. **整理任务上下文**：提取当前对话中与功能有关的问题、目标、用户角色、已确认决策、约束、范围外事项、项目/仓库信息和 issue tracker 配置。忠实传递事实；未知信息标注“未提供”，不得虚构。
4. **装配派发消息**：严格包含以下五部分，按顺序排列：
   - `【目标 Agent】`：用户明确指定的 Agent 标识；仅用于 acpx 路由和交付确认。
   - `【任务上下文】`：第 3 步提取的具体事实和项目配置。
   - `【Agent 执行指令｜必须遵守】`：`references/agent-instructions.md` **完整原文**。
   - `【Spec 模板｜必须严格使用】`：`templates/spec.md` **完整原文**。
   - `【交付指令】`：要求目标 Agent 完成 issue 发布、添加标签，并返回实际状态、issue 链接和主要测试接缝。
5. **通过 acpx 派发**：将以上完整消息交给**用户指定的目标 Agent**。本 Skill 不规定 acpx 的具体命令或参数，但**只允许通过 acpx 派发**；不得自行完成任务或更换 Agent。
6. **回传结果**：仅依据目标 Agent 的实际反馈说明执行状态。成功时返回 issue 标题、编号、链接、标签状态和测试接缝；失败或阻塞时返回原因。不得虚构发布结果或标签状态。

## 硬性约束

- **用户指定 Agent** 与 **两个文件的全文交付** 是派发前的必要条件；任一条件不满足都不能正常派发。
- 不得将 Agent 固定为 Kimi、Claude、Codex 或其他任何工具内置默认对象。
- “不访谈”不免除确认用户指定的**派发对象**，但不得借此访谈产品需求。
- 若用户尚未确认测试接缝，按 `references/agent-instructions.md` 的规则处理；编排者不替用户确认。
- `ready-for-agent` 由实际执行的目标 Agent 在 issue tracker 中设置，编排者不得代办。
- 不得降级成“编排者先写 spec，再交给 Agent 发布”。
