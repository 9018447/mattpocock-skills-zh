# implement-acpx：派发一组 tickets 实现

本 Skill 负责把一组已确定的实施 tickets 交给用户指定的 Agent，并把结果带回当前会话。编排者负责核对输入、探索相关上下文、写出可独立执行的 prompt、派发和汇报；目标 Agent 负责实现全部 tickets。编排者不接管实现。

## 前置条件

- **目标 Agent 必须由用户明确指定**，可来自当前请求或当前对话中明确适用于本次工作的指定。没有指定时，只问“要派发给哪个 Agent？”，然后停止。
- **tickets 必须已经确定**。用户可提供 issue 引用、链接或本地 ticket 文件。若没有明确的 ticket 集合，先请用户指定，不自行拆票。
- **项目和工作目录必须明确**。通过 ticket、链接或用户说明确定仓库；不要猜测仓库、分支或 issue tracker。
- **issue tracker 必须已配置**，若 ticket 引用需要从 tracker 读取。配置缺失时提示用户运行 `/setup-matt-pocock-skills`，然后停止。
- 只使用用户指定的 Agent 标识。若 acpx 无法连接该 Agent，说明具体错误并停止；不改派给其他 Agent，也不改为本地实现。

## 派发流程

1. **确定本次工作范围。** 解析所有 ticket 引用，读取 ticket 正文、验收标准、依赖、关联 spec 和 ADR。确认它们属于同一个仓库及本次指定的工作范围。若引用有歧义或彼此冲突，先指出具体冲突并请用户决定。完成标准：prompt 中列出的 ticket 集合与用户指定范围完全一致，且每张票都有可访问的来源。

2. **探索实现上下文。** 阅读相关代码、测试、项目约定和已存在的实现；按需查阅外部资料。优先使用官方文档和一手来源。把查到的结论、仓库内路径、外部来源链接，以及它们各自支持的结论写入 prompt。清楚区分已观察到的事实、来源内容和仍未确定的事项。完成标准：目标 Agent 无需依赖当前对话即可找到关键文件和来源，并知道哪些决策已经确定。

3. **写入派发 prompt。** 使用 `writing-for-agents` 的规则，把 prompt 保存到目标仓库中便于后续 Agent 读取的位置，例如 `prompts/implement-<feature>.md`。prompt 必须包含：
   - 全部 ticket 的引用、标题、来源和验收标准；
   - 相关 spec、ADR、代码路径、测试路径及探索发现；
   - 外部资料的链接与对应结论；
   - 明确目标：完成所有列出的 tickets，并报告每张票的结果；
   - 指示目标 Agent 按其环境中可用的 `/implement` 工作流逐张实施，并遵循 ticket 的依赖顺序；
   - 说明目标 Agent 是执行末端，不得继续派发任务或调用 acpx、subagent；
   - 未知事项、冲突和边界，以及完成后需要回报的提交、测试、阻塞和未完成项。

   只将用户已确认的决定写成要求。探索所得的事实应附路径或链接；推断须标明为推断，不得伪装成用户决定。完成标准：prompt 脱离本会话后仍能独立执行，且每项要求都有明确来源或被标为待决事项。

4. **通过 acpx 派发。** 在指定仓库目录中将 prompt 内容交给用户指定的 Agent。遵循 acpx 当前 CLI 的目标 Agent 命令和权限设置；保留派发结果及目标 Agent 的原始状态。完成标准：收到目标 Agent 的完成报告，或确认了明确的失败 / 阻塞原因。

5. **回传结果。** 汇总 prompt 文件位置、实际处理的 tickets、Agent 报告的提交或变更、验证结果、未完成项及阻塞原因。不要把 Agent 未报告或未验证的事项说成已完成。完成标准：用户能逐张判断 ticket 是否实现、证据在哪里、还需要做什么。

## 范围边界

- 一次调用派发用户指定的整组 tickets；不拆分新的 tickets，也不擅自略过其中任何一张。
- 目标 Agent 负责实现与验证。编排者不在本地补写代码，也不把失败任务转交给另一个 Agent。
- 如果 prompt 制作时发现 ticket 缺少关键决策，不代替用户补决定；把缺口列为待决事项并暂停派发。
- 如果目标 Agent 只完成部分 tickets，逐项报告状态，不将部分完成描述成整组完成。
