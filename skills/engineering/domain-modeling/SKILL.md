# Domain Modeling：用户指定 Agent，acpx 纯派发

本 Skill 不绑定 Kimi 或任何默认 Agent。**用户必须明确指定本次任务的目标 Agent**。编排者不得自行进行领域建模、修改领域文档或代替目标 Agent 回答领域问题。

## 前置条件

- 目标 Agent 必须由用户针对本次任务明确指定，或在当前对话中已有明确适用于本次任务的指定。没有指定时，只询问“要派发给哪个 Agent？”，然后停止。
- 不得根据上次派发、示例、可用性或模型偏好猜测 Agent，不得自动切换 Agent。
- 只能通过 acpx 派发。指定 Agent 不可用时报告阻塞，不得改成本地执行。
- 本 Skill 不强制要求 issue tracker 配置，领域文档不存在时由目标 Agent 按规则懒加载创建。

## 职责边界

**编排者只负责**：确认 Agent、整理用户对话中的领域事实与待解决问题、装配派发消息、通过 acpx 派发、原样传递目标 Agent 的澄清问题及用户答复、回传实际结果。

**目标 Agent 负责**：检查代码和已有领域文档、核对术语及边界、提出必要的精确澄清、判断 ADR 门槛、在术语确定时更新正确的 Glossary、编写符合格式的 ADR。

编排者不得擅自探索仓库、推导术语定义、决定领域边界、编写或修改 Glossary/ADR，也不得在派发失败后自行接管。

## 强制全文交付

每次派发前必须读取下列文件，并将**各自完整原文**嵌入 acpx 任务消息：

1. `references/agent-instructions.md`：领域建模全部执行规则、写作约束、交互边界及结果协议。
2. `templates/glossary.md`：Glossary 和多 context Glossary Map 的格式与归属规则。
3. `templates/adr.md`：ADR 模板、编号、触发门槛和可选结构。

这些文件是给目标 Agent 的**强制执行契约**，不是让编排者概括的参考资料。不得只传文件名、路径、链接或摘要，不得重写、省略、截断，也不得让 Agent “自行读取”。若消息容量不足以传递全文，停止派发并报告阻塞。

## 派发流程

1. **确认 Agent**。仅使用用户明确指定的标识进行 acpx 路由。
2. **整理上下文**。提取现有对话中已经确定的领域术语、争议、决策、约束及项目位置；没有证据的内容注明“未提供”，不要推断。
3. **装配派发消息**。依次包含：
   - `【目标 Agent】`：用户指定的 Agent 标识。
   - `【领域建模任务上下文】`：用户表达的具体问题、已有决策和项目上下文。
   - `【Agent 执行指令｜必须遵守】`：reference 文件全文。
   - `【Glossary 模板｜必须严格使用】`：Glossary 模板全文。
   - `【ADR 模板｜必须严格使用】`：ADR 模板全文。
   - `【交付指令】`：要求返回文档变更、未确定术语、必要澄清及真实状态。
4. **通过 acpx 派发给指定 Agent**。本 Skill 不规定 acpx 的具体命令或参数。
5. **处理澄清**。目标 Agent 发现必须由用户决定的术语/边界时，编排者仅转交问题；用户答复后仍通过 acpx 交给**同一个指定 Agent**继续处理，附上前述三个文件全文及必要的原任务上下文。编排者不替用户确认。
6. **回传实际结果**。说明哪些 Glossary/ADR 已更新、哪些问题仍待确认；失败时只报告实际原因，不虚构写入。

## 硬性约束

- 只允许用户指定的 Agent 执行建模与写入，编排者是纯派发者。
- 所有 references 和 templates **全文传递**是每次派发及后续恢复派发的必要条件。
- 确定的术语尽早落盘；未确认的概念不得当作事实写进 Glossary。
- ADR 只有满足严格三条件时才写入，不因本 Skill 被调用而强行生成。
- 不通过此 Skill 仅仅读取 Glossary；它的用途是主动修改领域模型。
