# acpx-domain-modeling：用户指定 Agent，acpx 纯派发

本 Skill 不绑定任何 Agent。**目标 Agent 必须由用户针对本次任务明确指定**，且只能通过 acpx 派发。编排者是纯派发者：只总结对话、装配 prompt、回传结果，术语核对、边界判断与文档写入全部由目标 Agent 完成。

## 前置条件

- 目标 Agent 必须来自用户的明确指示：当前请求，或当前对话中明确适用于本次任务的指定。没有指定时，只询问“要派发给哪个 Agent？”，然后停止。
- 仅用用户指定的 Agent 标识做 acpx 路由，不改名、不替换、不兜底切换。目标 Agent 无法通过 acpx 使用时报告阻塞，请用户重新指定，不改成本地执行。
- 本 Skill 不要求 issue tracker 配置；领域文档不存在时由目标 Agent 按规则懒加载创建。

## 派发流程

1. **确认目标 Agent**。按前置条件取得用户指定的标识。完成标准：拿到 Agent 标识。
2. **总结上下文为 prompt 并落盘**。把当前对话中已确定的领域术语、争议、决策、约束及项目位置整理成派发 prompt，写入项目目录下的 prompt 文件（如 `prompts/`）。没有证据的内容注明“未提供”，不做推断。prompt 中显式写明四点：
   - 触发 `\domain-modeling` skill（执行侧技能名，保持无前缀）执行领域建模；
   - 产出直接落盘到项目目录（GLOSSARY.md 与必要的 ADR），无需回询确认；
   - 目标 Agent 是执行末端，不得继续向下派发，不得使用 acpx 或 subagent；
   - 完成后回传实际文档变更与仍待确认的术语。

   完成标准：四点齐备，prompt 脱离当前对话仍能独立交代任务。
3. **通过 acpx 派发**。交给用户指定的 Agent 执行，编排者不接管、不代写。完成标准：拿到目标 Agent 的实际执行结果。
4. **转交澄清**。目标 Agent 提出必须由用户决定的术语或边界问题时，原样转交；用户答复后交回同一个指定 Agent 继续。完成标准：每个澄清都有用户答复或明确标注待定。
5. **回传结果**。说明哪些 Glossary、ADR 已更新，哪些问题仍待确认；失败时只报告真实原因。完成标准：用户能据此知道领域文档发生了什么变更。

## 产出与用户确认

用户确认即完成。用户提出异议时，编排者按异议做小修后再交确认；小修只限用户指出的异议本身，有异议直接修改, 无需派回Agent，除非用户明确要求。

## 硬性约束

- 确定的术语尽早落盘；未确认的概念不得当作事实写进 Glossary。
- ADR 只有满足严格三条件时才写入，不因本 Skill 被调用而强行生成。
- 本 Skill 的用途是主动修改领域模型，不是只读查询 Glossary。
