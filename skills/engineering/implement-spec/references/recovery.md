# 异常处理与恢复协议

SKILL.md 主流程的异常分支收在这里，命中对应情况才读本文件。

## 额度撞限降级（不等重置）

候补链任一 agent（omp/kimi/dsh 同样处理）撞 5h 用量上限——错误签名如 `1308`、`Usage limit reached for 5 hour`、`AccountQuotaExceeded`，retry-after 数小时——**不等重置、不干等**：同 prompt、同 worktree（半成品原样保留续做）改派链内下一 agent。旧 agent 日志换名留档，pane 已被回收则重建 tab 取新 pane_id。降级重派不改票面验收标准，续作 agent 从盘上现状接手（判据同「中断续作」）。（2026-10-09 用户裁定"别卡死 用kimi"）

## acpx 静默死亡恢复

日志无任何错误标记、无 `[done] end_turn`、worktree 零改动 → 判静默死亡（2026-10-09 t07 首派实证，无已知死因）：留档日志（`mv <log> <log>.attemptN.log`）后原样重派，两次连死才升级诊断。pane 随命令结束被回收，重派前必须 `herdr tab create` 重建并取新 pane_id。

## 异常降级前先审计盘上现状

判异常降级前先审计盘上现状保留成果——半成品不是交付，丢弃前必须留档。

## 中断续作

任务中断后续作时，先审计盘上现状（含各 worktree 的分支状态），保留符合 Ticket 的已有成果，再补完剩余验收，不得默认推倒重来。handoff 中记录中断和续作事实。

**续作分工（2026-09-30 票 04 定案）**：预算耗尽/中断后的续作，编排者只做审计、环境排障、冻结成果清点；票内实现、长计算、数据回填、提交一律通过**新的派发**回到实现 agent——这是实现票模板固定段第 6 条「不提交」的唯一例外，续作 agent 在 `ticket/{{tNN}}` 分支上提交。编排者不得以"上下文在手"为由自行实现——2026-09-30 票 04 编排者接手实现与计算后被用户纠正。

## 进程存活核查

- 查看进度仅短暂读取日志，不阻塞轮询。
- `[done] end_turn` 后若包装进程仍存在，用已记录 PID 经 `ps -p <pid>` 确认后清理，不用 `pgrep -f`。
- 进程存活核查一律用 `pgrep -fa 'patter[n]'`（尾字符加括号防自匹配）或直读 `/proc/<pid>/cmdline`；本环境 `ps` 输出可能被 rtk 包装丢 CMD 列，禁止 `ps aux | grep` 判存活——2026-09-18 曾因此误判存活进程已死。
- **watcher/核查命令里的日志路径也是自匹配源**（2026-10-10 t12 实证）：`pgrep -f` 匹配整条命令行，watcher 命令里 tail/grep 引用的日志文件名含任务标识（如 `kimi-t12-batchdist.log`），模式加了括号、路径没加，进程死了 watcher 永远匹配自己不退出。修法：同一命令里路径出现处同样加括号（`…batchdis[t].log`，shell 展开 path 不受影响），或存活核查一律走 `ps -p <pid>`。写完 watcher 自查一遍：命令行里任务标识的每一处出现是否都不可被自己的模式匹配。

## 配额错误签名的自动换链

启动探针阶段日志出现 `quota|usage limit|403.*limit` 类签名即视为 agent 不可用，直接按候补链换派（omp→kimi→dsh），不等用户报障、不等重置——2026-10-10 t12 实证：kimi 周配额 403（7 天窗）与 dsh 5h 窗两种签名先后出现，链头 omp 救回，全程约 4 分钟。周配额与 5h 配额签名同处理，错误文本里带重置时间且重置点在几分钟内的，换链仍优先于等（等是链内无人可用时的兜底）。
