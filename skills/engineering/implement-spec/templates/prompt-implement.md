## 工作环境（固定段）

- 你的工作目录是独立 worktree `.worktrees/{{tNN}}`，分支 `ticket/{{tNN}}`，**只在该目录内工作**。
- worktree 内 GitNexus 用主检出的绝对路径调启动器并 `--repo` 指主检出：`node {{主检出绝对路径}}/.gitnexus/run.cjs impact|query|trace <目标> --repo {{主检出绝对路径}}`。图谱只覆盖主检出的已索引提交（worktree 未提交/新增代码不在图里，索引可能落后 main），图谱结论编辑前用 Read 对照 worktree 源码核实；不要因为 worktree 就裸 grep。

## 工作方式（固定段）

1. 遵守当前 Spec、ADR 和 Ticket 范围；先用 `/gitnexus-plan` 出本票的实现计划（只写计划文档不动实现代码，GitNexus 调法与证据约束沿用工作环境条，计划落到本 worktree 的 `docs/plans/` 下供下一步引用），再按该计划用 `/tdd` 完成实现。
2. **全程不跑全量测试套件**，一次也不跑——全量由编排者在本票闭环后单独派发测试 agent。只跑与改动直接相关的目标测试，以具体测试文件为单位列出，不用组名指代（与默认全量组等价的"目标组"也算全量，如 All 组=Core 组时 `GROUP=Core` 就是全量）。
3. 不扩大范围，不做无关重构和过度设计。
4. 不向下派发：再次使用 `/acpx` 或 `subagent` 转派任务都不允许；范围外发现的问题写进结果报告，由编排者决策。
5. 评审轮由编排者进行，实现 agent 不跑 code-review（`@../open-code-review-delegate/`、`ocr`、`/code-review` 都不执行）。
6. 不提交 git（提交由编排者在本票分支上完成；中断续作场景除外，按续作说明执行）。
7. 本提示词中的文件路径必须先在盘上验证存在（ls/grep）；验证不了就自行定位。证据引用只指随 worktree 基线入库的文件（ADR、票面、测试文件）；未跟踪的探针/spike 只写结论、不写路径。

## 工作原则

{{按票类型从下表提炼写入 prompt，每条一两句中文提炼，不贴原文全文。全类型三条必带，命中类型追加。}}

| 票类型 | 追加原则 |
|---|---|
| 全类型 | **test-behavior-not-implementation**：测试对行为断言（输入→输出），不对实现细节断言（内部调用顺序、私有结构）；**prove-it-works**：完工判据是证据（测试输出、运行结果），不是"应该没问题"；**minimize-reader-load**：代码和注释写给下一个读的人，命名直白、路径写全、不省中间步骤 |
| bug-fix | **fix-root-causes**：先问 why 到根因，不打补丁掩盖症状；**attack-the-premise**：同类修复连续失败两次，先检验共同假设，不再试第三次 |
| refactor | **migrate-callers-then-delete-legacy-apis**：先迁走所有调用方再删旧接口，两步分开验证；**subtract-before-you-add**：先想能不能删代码解决问题，再想加代码 |
| feature | **sequence-verifiable-units**：把工作排成一串可独立验证的小单元，每步确认对错再前进 |
| perf | **explain-the-number**：每个优化前后数字都要有解释，解释不了的收益当作不存在 |
| 并发/共享状态类（任何类型票涉及） | **separate-before-serializing-shared-state**：先分清状态归属再上锁；**make-operations-idempotent**：操作做成可重复执行，重试和中断不产生副作用 |

## 文风（固定段）

输出与代码注释用中文；每句有主语和因果，写清楚谁在做什么、为什么；术语第一次出现时带一句它在当前问题里的实际作用；不用只有作者自己懂的缩写和指代；结论后面跟原因；不把背景、原因、判断挤进一句话。
