# acpx-to-spec：用户指定 Agent，acpx 纯派发

本 Skill 不绑定任何 Agent。**目标 Agent 必须由用户针对本次任务明确指定**，且只能通过 acpx 派发。编排者是纯派发者：只总结对话、装配 prompt、回传结果，spec 的探索、撰写与发布全部由目标 Agent 完成。

## 前置条件

- 目标 Agent 必须来自用户的明确指示：当前请求，或当前对话中明确适用于本次任务的指定。没有指定时，只询问“要派发给哪个 Agent？”，然后停止。这只是确认派发对象，不是需求访谈。
- 仅用用户指定的 Agent 标识做 acpx 路由，不改名、不替换、不兜底切换。目标 Agent 无法通过 acpx 使用时报告阻塞，请用户重新指定，不改成本地执行。

## 派发流程

1. **确认目标 Agent**。按前置条件取得用户指定的标识；缺失则询问并停止。完成标准：拿到 Agent 标识。
2. **总结对话为 prompt 并落盘**。把当前对话中用户已确定的需求总结成派发 prompt，使用`writing-for-agents`写入项目目录下的 prompt 文件（如 `prompts/`）。只总结用户说过的内容，不添加对话之外的推断。完成标准：prompt 脱离当前对话仍能独立交代需求。
3. **装配派发指令**。在 prompt 中显式写明五点：
   - 触发 `\to-spec` skill（执行侧技能名，保持无前缀），
   - 用户对话上下文的详细总结(没有可跳过) ;
   - 相关 ADR 的位置；
   - 产出明确为仅spec,**不含tickets**直接落盘到项目目录，无需回询确认；
   - 目标 Agent 是执行末端，不得继续向下派发，不得使用 acpx 或 subagent。
   完成标准：五点齐备，prompt 脱离当前对话仍能独立交代任务。

完成标准：五点齐备，可直接派发。
4. **通过 acpx 派发**。交给用户指定的 Agent 执行，编排者不接管、不代写。完成标准：拿到目标 Agent 的实际执行结果。
5. **回传结果**。原样回传 issue 链接、落盘位置与 Agent 报告的状态；失败或阻塞时只报告真实原因。完成标准：用户能据此看到 spec 在哪里、是否发布成功。

## 产出与用户确认

用户确认即完成。用户提出异议时，编排者按异议做小修后再交确认；小修只限用户指出的异议本身，是编排者唯一可以亲手改动 spec 的场合，除非用户明确要求，否则不再重新派回Agent.
本产出只包含spec，不含tickets。
